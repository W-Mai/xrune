IWhat it is

One Casting, Many Inscriptions

Write a casting in xrune's declarative DSL. A runesmith you bind — any type implementing the eight-method DsRune trait — inscribes it into whatever code your host actually needs: ECS spawn calls, a render-tree builder, a debug echo, a formatter round-trip.

The DSL only parses. Widget names are any identifier and attribute values are any Rust expression, so every shred of meaning lives in the rune you bind.

IVThe Covenant

      
The Eight Runes

      
A rune is any type that implements DsRune: eight methods, no defaults. decipher calls one per node; your rune decides what each becomes.

    

    

      

      

    

    

      

        
Host it in your own proc-macro

        
ui! hard-wires DefaultRune. A real backend ships its own proc-macro crate and swaps in its rune; downstream users write the same DSL.


#[proc_macro]
pub fn my_ui(input: TokenStream) -> TokenStream {
    let root = parse_macro_input!(input as DsRoot);
    let mut rune = MyRune::new();
    rune.inscribe_root(&root.get_parent());
    decipher(&root.get_content(), &mut rune);
    TokenStream::from(rune.seal())
}

      

      

        
The one foot-gun

        
decipher never walks the children it hands you. Every inscribe that receives them must recurse itself. Forget it and the subtree vanishes, without a word.


fn inscribe_widget(&mut self, name: &syn::Ident, /* … */ children: &[DsTreeRef]) {
    /* … emit code for `name` … */
    for child in children {
        decipher(child, self); // omit this and the subtree disappears
    }
}

      

    

  






  

    

      
VThe Nexus

      
Five Volumes and a Hub

    

    

      
      
        xrune-sigil
        The sigil-forge
        #[derive(DsRef)] mints the Rc<RefCell> handles the tree is built from.
      
      
        xrune-nexus
        The hub
        The AST, the DsRune trait and the decipher walk. Everything binds here.
      
      
        xrune-incant
        The speaking-stone
        The ui! { … } proc macro, bound to DefaultRune.
      
      
        xrune
        The opening scroll
        The one dependency you add. Re-exports the hub and ui!.
      
      
        xrune-fmt
        The scribe
        Rewrites every ui! { … } through the real parser. The Forge runs its formatter.
      
      
        mirui-macros
        A host in the wild
        Depends on xrune = "1.10"; its ui! is a rune.

VIIThe Choice

      
When to Reach for It

    

    

      

        
        
Plug-in code-gen

        
One DSL, many runes. The same casting can become spawn calls, a render builder, a static analyzer.

      

      

        
        
Untyped at parse time

        
Widget names are arbitrary idents; attribute values are arbitrary syn::Expr. All semantics live in the runesmith you bind.

      

      

        
        
Built for hosting

        
Ship your own proc-macro crate, bind your own runesmith, and downstream users write the same DSL with your code-gen.

      

    

    
Need compile-time types on widget names and attribute keys? Reach for a typed-builder DSL such as leptos::view!, dioxus::rsx! or yew::html!. Read the comparison →
